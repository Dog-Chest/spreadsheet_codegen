# 踩坑表：症状 → 成因 → 修法

来源：本仓库 `abs_fpi/` 的实测报告（`FINDINGS.md`，对一个真实船舶规范移植项目的逐轮试用）、
`abs_fpi/TEMPLATES.md` 的踩坑表，以及在 0.11.x 上重新实测的结论。

**注意版本**：`FINDINGS.md` 记录的是 0.1.0–0.5.0 时期的缺陷，**其中大部分已经修掉了**。
下面标了「已修」的只在遇到老版本时才有意义；**加粗的条目是 0.11.x 上仍然成立的**。

---

## 1. "看起来成功了，其实没有"——最危险的一类

| 症状 | 成因 | 修法 |
| --- | --- | --- |
| **跑完 `render` 说成功，但工作簿 / 文件没变** | 没给 `--write-excel` 也没给 `--outdir` → **只预览** | 明确加 `--write-excel` / `--outdir`。0.11.0 起摘要里永远有「写回 Excel │ 是 / 否（需要 --write-excel）」这一行，**读它**；不写回时还有一条 `!` 提示 |
| **导出的文件只有一条记录**（N 个 Case 写成同一个名字） | `filename` 里没带变量，N 份结果互相覆盖，最后只剩一份 | 0.11.0 起**写盘前就拦住**并给出验证过的改名建议。改成 `"{{ case_name }}.jsonl"` 之类；确实只想要最后一份才加 `--allow-overwrite-filename` |
| **模板改了，表里的代码没变** | 公式模式把公式**文本**写进了格子，改 YAML 必须重跑一次 | `render --write-excel` 刷新。改**参数**不用重跑，改**模板 / 变量定义 / 引擎**必须重跑 |
| **CI 说成功，其实输出是过期的** | 只跑了 `render`，没跑 `check` | CI 里加 `check`（过期 → 退出码 `3`）。`check` 用"重渲染 + 逐行比对 + 指纹比对"，同时能抓"改了参数没重跑"和"输出表被手改过" |
| **`init --force` 把填好的参数清空了** | `init` 是**重建**表格，不是增量 | 工具会比参数指纹并拦一次；确认要丢就 `--yes`。**填写前先 git / 复制备份**（原文件不自动备份） |

## 2. 公式模式（`engine: excel`）

| 症状 | 成因 | 修法 |
| --- | --- | --- |
| **`公式模式不支持 {% for %}` / 过滤器** | 模板里有 Jinja 循环、`{% %}` 跨行、或 `\|` 过滤器 | 见 `engine-preflight.md`：**优先把差异改成参数**（多开几个纯替换变量），实在不行才改 `engine: snapshot` |
| **白白放弃了公式模式** | 以为"目标代码里有 `if/else` 就不能用公式模式" | ❌ 错。目标语言自己的 `if / else / { } / for` 只是**字面文本**。真正拦住公式模式的是 *Jinja* 的控制流 |
| **`{% if draft > 20 %}` 报错** | 条件里裸写了变量 | 写 `draft.value > 20`。规则与 `case_filter`、`asserts` 一致 |
| **`{% if %}` 跨行就报错** | 公式模式是"一行模板 → 一个单元格"，跨行分支改变行数 | 把 `{% if %}…{% endif %}` **整段压在同一行内** |
| **单个单元格报"公式太长"** | 一个 `{{ x }}` 展开 300–500 字符（`INDEX`+`MATCH`+`ISBLANK`+回落+前后缀） | 一行别放 8 个以上占位符；拆行或改 `snapshot`。硬上限 **8192 字符/格** |
| **加了几列 Case，`check` 报 `value_mismatch`** | 值列用的是**相对列**（`E:E`），列一移位就指错工况 | 重跑 `render --write-excel`。**插删变量行不用重跑**（按变量名 `INDEX/MATCH` 定位） |
| **Excel 里看着对，导出的文件不对**（或反过来） | 公式模式"值只活在 Excel 里"；`--outdir` 是 Python 渲染的 | 正常情况下两者等价（模板纯替换）。跑 `check --values`（默认开）拿证据；`bool` 与区域设置是两个已知差异 |
| **`bool` 变量在 Excel 里是 `TRUE`，导出是 `true`** | 已知差异 | 用 `type: string`，或该模板用 `snapshot` |
| **欧洲区域下小数形态变了** | 区域设置影响 Excel 的数值→文本 | 换区域前先验一遍 |
| **改输入后派生参数没重算** | 表达式里有 `round` / `ceil` / `upper` 等**翻译不了**的函数 → 降级成"写死 Python 算好的值" | `validate` / `render` 会告警列出降级的参数名。改输入后要重跑 `--write-excel`；或改用能翻译的写法 |

## 3. 配置

| 症状 | 成因 | 修法 |
| --- | --- | --- |
| **错误在三步之后才以另一种形式冒出来** | YAML **同键重复**（PyYAML 默认静默覆盖）。**已修**：0.6.0 起按行号报错 | 常见于写了两块 `variables:`。按行号合并 |
| **`变量 'draft' 的 default 在两处不一致`（告警）** | `extends` 合并时同名变量的 `default` / `description` 不同 | 只告警，保留先出现的。决定性的字段（`prefix`/`suffix`/`type`/`derived`/约束）不一致会**直接报错** |
| **`output_sheet 'X' 未在 excel.sheets.outputs 中声明`** | 模板输出表没登记 | 在 `excel.sheets.outputs` 里加 |
| **`变量名 'a-b' 不是合法标识符`** | 变量名会**直接当 Jinja 变量名**用 | 只能 `[A-Za-z_][A-Za-z0-9_]*`；保留名 `case_name` / `template_name` 不能用 |
| **模板引用了 Excel 里临时加的变量，`validate` 有提示** | 表里多出来的变量行**允许**存在（按 `auto` 读进上下文） | 这是有意设计。但 `validate` 会对"模板引用了但 YAML 未定义"提示；确认无误后补回 YAML，别让参数长期游离 |
| **`定义了却没人用的变量`**（0.6.0 起会报） | 变量名拼错 —— 这是"改了参数没生效"最典型的来源 | 按 `validate` 的点名核对 |
| **`min` / `max` 配在 `type: string` 上直接报错** | 范围只能给数值类型 | 改 `type`，或改用 `pattern` |
| **下拉列表没出现 / 直接报错** | Excel 数据有效性两个硬限制：选项**不能含逗号**；拼起来 **≤ 255 字符** | 拆成多个变量，或改用 `pattern`（只由工具检查） |
| **声明了约束后，新加的 Case 列直接报错** | 声明约束 = "必须给一个合法取值"，**空值默认不合格** | 这是**故意的**，正好治下面那条。某类型才有的字段写 `allow_blank: true` |
| **清空了单元格却回落到默认值** | `default` 默认同时承担"预填"和"回落" | 这种字段写 `fallback: false`（清空即表示"没有这个字段"）。`prefill: false` 则连新表都不预填 |

## 4. 工作簿结构

| 症状 | 成因 | 修法 |
| --- | --- | --- |
| **新加的 Case 列悄悄进了某个规则集** | `case_filter` 用的归属变量（如 `kind`）留空 → 回落 `default` | **先填归属变量再填别的值**。给 `kind` 加 `choices` 能把这类错误变成硬报错；`render` / `check` 也会对"整列都空的 Case"提示 |
| **改动布局后读不到旧数据** | `local_direction` 改变的是**表的形状** | 切布局 = 重做工作表：备份 → `init --force` → 重填 → 重跑 |
| **纵向布局少读了几行工况** | 纵向布局从第 2 行起扫描，**遇到第一个空 A 格就停** | 行必须连续，中间别留空行 |
| **Output 表里残留旧代码**（模板改短 / Case 变少） | **已修**：0.2.0 起按"真实底边"清理 | 若在老版本上遇到，重跑 `render --write-excel` |
| **`Template` 隐藏表改了没用** | 真源是 YAML，它只是快照 | 改 YAML，别改那张表 |
| **`无法写回 Excel … 文件被 Excel 占用？`** | 工作簿正在 Excel / WPS 里开着 | **让人关掉**再重试。退出码是 `4`，属于环境问题、不是配置错误 |
| **输出里出现 `None`** | 变量既没值也没 `default` | 给 `default: ""` |
| **渲染结果里莫名多出空行** | **Jinja 的空行也各占一行**，而公式/快照都是"模板一行 → 结果一行" | 用 `{%- ... -%}` 控空白。对"逐行写进 Excel 再整列复制"的用法尤其重要 |
| **右上角拖拽后公式指错工况** | 手加 Case 列后没重跑 | 见 §2。工具写出的每格公式指向的是**真实**的 Case 轴，但结构变了要刷新 |

## 5. 被旧文档 / 旧经验带偏的（已在 0.11.x 实测更正）

这一节专门写给"有旧记忆"的你。**先信实测，再信文档。**

| 旧说法 | 现状（0.11.0 实测） |
| --- | --- |
| 「公式模式下 `case_filter` 的工况**必须相邻**」（`TEMPLATES.md` §4，0.3.0 时代） | **不成立**。实测 `EXT, INT, EXT` 这样交错排布，写出的公式是 `E$1` 与 `G$1` —— 用的是**真实 Case 轴**，`check` 通过。别再为了"必须相邻"去重排用户的工况 |
| 「`render` 成功 = 写进去了」 | 不是。默认**只预览**（0.2.0 起摘要会明说） |
| 「Prefix/Suffix 会被 strip」 | **已修**（0.2.0）。现在**非空值原样使用，空格有意义**；只有"单元格留空 / 只敲空格"才回落 YAML |
| 「YAML 同键重复会被静默吞掉」 | **已修**（0.6.0）。现在按行号报错 |
| 「`validate` 不查"定义了没被引用"的变量」 | **已修**。现在会报 |
| 「`init --cases` 只接受整数」 | **已修**。现在也接受名字：`--cases EXT-T20.559,INT-T15` |
| 「`{{ x.value }}` 不过整数浮点规范化」 | **已修**。两种写法（`{{ x }}` / `{{ x.value }}`）形态一致，不会再出 `340.0` |
| 「有 `if/else` 就不能用公式模式」 | **从来没对过**（0.4.0 已更正）。见 §2 |
| 「`check` 报过期一律退出码 1」 | 不是。0.11.0 起是 `3`（输出过期）/ `2`（配置取值）/ `4`（环境）。老脚本的 `if errorlevel 1` 仍然有效，但分流要看新码 |

## 6. 工具管不着的（别指望它）

| 事项 | 说明 |
| --- | --- |
| **生成代码的语义正确性** | 它不认识 C / GeniE / NASTRAN 的语法。`Math.sin(90)` 照过。业务规则要靠**下游校验器**（`abs_fpi` 用了四层：`validate` → `check`（含公式求值）→ 独立求值器 → 与另一套实现逐行比对） |
| **"`if` 必须配 `else`"这类目标语言硬规矩** | 模板是纯文本，工具不会替你查。写进交付话术或加下游检查 |
| **单个变量跨 Case 联动** | 每个 Case 的取值互相独立。要在 Excel 里用公式实现 |
| **超过三层的作用域**（舱里再分部件） | 表达不了。把最下层摊进成员表 |
| **超大工作簿性能** | `openpyxl` 全量加载。万行以内没问题，更大就按规范集 / 分段拆工作簿 |
| **规范 / 标准本身的版权** | 往模板库塞规范原文或表格前，先确认授权（本仓库的 `NOTICE.md` 就是这个口径的样板） |
