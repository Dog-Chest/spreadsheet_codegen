# 工作簿布局：人在哪张表、哪一列填

这个工具的一半价值是"把参数填写变成一张人人会填的表"。所以你必须能**准确地说出**
"打开这本工作簿，在 X 表的 Y 列填 Z"，否则用户拿到文件也不知道从哪下手。

下面所有列号都是从 `init` 生成的真实工作簿里量出来的（0.11.x）。

---

## 1. 工作表清单与职责

| 表 | 谁写 | 内容 |
| --- | --- | --- |
| `HOWTO` | 工具 | 放在**第一张**。使用说明 + **生成记录**（时间 / 参数指纹 / 输出指纹 / Case 列表 / 生成命令） |
| `Global Parameter` | **人**（工具预填） | 全项目共用一份的参数 |
| `Local Parameter` | **人**（工具预填） | 每个工况一份的参数；工况的"轴"在这张表 |
| 成员表（如 `Tank Data`） | **人**（工具预填） | 第三层作用域：一行一个舱 / 设备 / 器件 |
| `Output` / 自定义输出表 | **工具** | 渲染结果。公式模式里是活公式 |
| `Template` | 工具（隐藏） | 模板原文与元信息快照 |

名字都可以改：`excel.sheets.global` / `.local` / `.outputs`、`excel.template_sheet`、
`excel.howto_sheet`（设成 `null` 就不生成）。成员表名由 `variables.group.sheet` 决定。

> **`Output` 表不要手改。** 下一次 `render --write-excel` 会覆盖它。
> `Template` 隐藏表可以编辑，但**改了没用** —— 真源是 YAML。

## 2. `Global Parameter`：`A`=变量名，`B`=值

实测表头（第 1 行）与数据：

| | A | B | C | D | E |
| --- | --- | --- | --- | --- | --- |
| 1 | `Variable` | **`Value`** | `Description` | `Prefix` | `Suffix` |
| 2 | `L` | `340` | 规范船长 [m] | | ` m` |

**让用户填 `B` 列。** `C` 是描述（只读性质的注释），`D` / `E` 是前缀后缀 ——
**可以覆盖，但是按变量而不是按工况**，所以一般不用动，改 YAML 更清楚。

> `unit` 字段是**纯文档**：只进批注与 `validate` 清单，不进生成结果。要让单位出现在代码里，
> 用 `suffix`（`suffix: " m"` → `340 m`；**前导空格有意义**）。

## 3. `Local Parameter`：工况的轴在这里

### 3.1 横向（默认，`local_direction: horizontal`）——一个工况一列

| | A | B | C | D | E | F | G |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `Variable` | `Description` | `Prefix` | `Suffix` | **`EXT-A`** | **`INT-A`** | **`EXT-B`** |
| 2 | `kind` | | | | `EXT` | `INT` | `EXT` |
| 3 | `draft` | | | | `20.5` | `15` | `22` |

- **`E1` 起是工况名**（`{{ case_name }}` 的来源），**`E2` 起是这个工况的取值**。
- **加一个工况**：在右边一格写工况名 + 往下填这一列的值。列必须**连续**，中间不能空列。
- **"右拉即增列"**：公式模式下，把输出格向右拖会自动换到下一个工况。

### 3.2 纵向（`local_direction: vertical`）——一个工况一行

| | A | B | C |
| --- | --- | --- | --- |
| 1 | `Case` | `kind` | `draft` |
| 2 | **`LC1`** | `EXT` | `20.5` |
| 3 | **`LC2`** | `EXT` | `15` |

- **`A2` 起每行非空的 A 列就是一行工况**；第 1 行 B 列起是变量名。
- **加一个工况**：选中整行 → 填充柄下拉 → 改 A 列的名字。
- 行必须**连续**，从第 2 行开始，**遇到第一个空 A 格就停**，中间不要留空行。
- **纵向布局没有 Prefix / Suffix 列**：前后缀只来自 YAML（点变量名那格的批注能看到）。
  需要按工况改前后缀就用横向布局，或把它拆成独立变量。

### 3.3 什么时候该选纵向

有些数据天然是"行"的：NASTRAN 的 `SUBCASE` / `SUBCOM` 工况控制语句、从别的表格整块拿到的
字段清单。纵向布局能**整块复制粘贴**，不用逐列转置。这是 `local_direction` 存在的唯一理由。

> **切换 `local_direction` 等于重做工作表**：形状变了，工具读不回旧数据。
> 先备份参数 → `init --force` 重建 → 重新填 → 重跑。

## 4. 成员表（第三层作用域）：一行一个成员

| | A | B | C | D | E |
| --- | --- | --- | --- | --- | --- |
| 1 | `成员` | `rho_tank` | `l_tank` | `b_tank` | `h_tank` |
| 2 | **`WBT6`** | `1025` | `42` | `32` | `32` |
| 3 | **`WBT7`** | `1025` | `14.5` | `10.15` | `32` |
| 4 | **`COT1`** | `900` | `42` | `32` | `32` |

- 表头就是变量名（A1 是 `成员`），**一行一个舱 / 设备**。
- 加一个成员：**直接插一行**。成员是从表里发现的，不用回头改 YAML（`members:` 只决定
  `init` 时先建哪几行）。
- 模板里照常引用 `{{ l_tank }}` —— 取值来自"这个工况的 `key` 指向的那个成员"。

配置长这样：

```yaml
variables:
  local:
    - name: tank_ref              # 每个工况用它指向一个成员（必须是 local）
      choices: ["WBT6", "WBT7", "COT1"]
  group:
    sheet: "Tank Data"
    key: tank_ref
    members: ["WBT6", "WBT7", "COT1"]
    variables:
      - {name: l_tank, type: float, default: 42, unit: "m"}
```

**作用域优先级（低 → 高）**：成员(group) → global → local → `case_name`。
三类变量的**名字不能重名**（配置阶段就报错）。成员表变量**不能用 `derived`**。

### 什么时候用成员表

| 场景 | 用不用 |
| --- | --- |
| 一个舱 / 设备被**多个工况**引用，参数只该写一遍 | ✅ 用 |
| 参数确实每个工况都不一样（工况特定系数） | ❌ 放 local |
| 所有工况都一样的船体主尺度 | ❌ 放 global |
| 需要**两层以上**引用（舱里再分部件） | ⚠ 表达不了，把最下层摊进成员表 |

## 5. 给用户的交付话术（照抄）

> 打开 `xxx.xlsx`：
> - **`Global Parameter`** 的 **B 列**填全项目共用的参数；
> - **`Local Parameter`** 的 **E 列起**（一列一个工况）填每个工况的参数 —— 表头 E1 起是工况名，
>   要加工况就在右边加一列，填上名字和值；
> - **`Tank Data`** 一行一个舱，加舱就插一行；
> - `Output` 表里是**公式**：改完参数**打开 Excel 就自动重算，不需要跑任何命令**；
> - 只有要把代码**导出成文件**、或者 CI 要检查时，才回到命令行跑
>   `spreadsheet-codegen render -c xxx.yaml --outdir generated/`。
> - 工作簿里第一张 `HOWTO` 表写着"本次生成时间 / 命令 / 指纹"，`check` 靠它判断是否过期。

## 6. 参数表里会长出来的"计划外"东西

| 现象 | 说明 |
| --- | --- |
| 表里多了一行 YAML 未定义的变量 | **允许**：会被读进上下文（按 `auto` 类型）。`validate` 会提示"模板引用了但 YAML 未定义"，建议确认后补回 YAML |
| 单元格写的是 Excel 公式（如 `=L/10`） | 允许，Excel 里能算；但 `openpyxl` 离线读不到值，`check` 会降级成"只比公式"并给提示 |
| 前缀 / 后缀格里留空 | 回落 YAML 的 `prefix` / `suffix`。**想清掉 YAML 里的前后缀只能改 YAML** —— 空单元格被当作"未填写" |
| 值格里只敲了空格 | 也视为未填写 → 回落 `default`。**非空值原样使用，不会被 strip** |
| 派生参数格是淡绿色 | 它是**自动计算**的，手工填的东西会被忽略（`render` / `check` 会告警） |

### `default` 的两种用途（0.11.0 起可分开控制）

| 用途 | 触发时机 | 关掉它 |
| --- | --- | --- |
| **预填** | `init` 建表时把 `default` 写进新单元格当提示值 | `prefill: false`（新表格留空） |
| **回落** | 读取时单元格为空 → 用 `default` 顶上 | `fallback: false`（空就是空） |

默认两个都开（与老版本行为一致）。**"某类型才有的字段"是典型场景**：银行卡记录本来没有
`url`，把格清空却回落出默认 url，导出的数据里就多了一个不该有的字段且**不报错**。
这种变量写 `fallback: false`。

### 取值约束会写进工作簿

声明了 `choices` 就是 **Excel 下拉列表**，`min` / `max` 就是**数值范围校验** —— 这是"帮人填对"。
真正的**判据**是工具侧的 `check_value_constraints`（下拉可以被粘贴绕过）。
`pattern`（正则）Excel 表达不了，**只由工具检查**。

> 两个硬限制（超了直接报错）：下拉选项**不能含逗号**；所有选项拼起来 **≤ 255 字符**。
